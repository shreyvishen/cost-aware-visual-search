Cost-aware visual search

I fine-tuned Qwen3.5-4B to use a zoom-in tool, so it decides where to look in a high-resolution image instead of reading all of it. The reward grades it on correctness and latency — real milliseconds I measured on the machine it ships to. Two runs, identical except that one term.

1The reward

The whole project lives in one line.

reward = correct ? (1 − λ · cost_ms) : 0 cost_ms = 1.411·vision_tokens + 13.198·decode_tokens + 101.79·zooms
No cost
λ = 0

Get it right and you score 1, get it wrong and you score 0. Nothing else enters the reward, so looking and thinking are free.

Cost-aware
λ = 5.85e−5

The same, minus what the episode actually cost in milliseconds. I fitted those three coefficients on an M4 Max rather than guessing them.

Notice the cost sits inside the correct branch. Answer wrong and you get 0 no matter how fast you were, so the model can never buy speed by being wrong.
