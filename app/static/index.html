Cost-aware visual search

In this project I fine-tune Qwen3.5-4B to use a zoom-in tool, so it can decide where to look in a high-resolution image instead of reading the whole thing at once. The interesting part is the reward: we grade it on correctness and latency, where latency is milliseconds I measured on the machine the model actually ships to, not a token count standing in for one. We train two runs that are identical in every way except that one term, and the cost-aware run matches the baseline's accuracy while running 2.18× faster on device. What surprised me is where the saving came from.

1The reward

Let's write down what we are actually optimising, because the whole project lives in one line.

reward = correct ? (1 − λ · cost_ms) : 0 cost_ms = 1.411·vision_tokens + 13.198·decode_tokens + 101.79·zooms
No cost
λ = 0

Get it right and you score 1, get it wrong and you score 0. Nothing else enters the reward, so looking and thinking are free.

Cost-aware
λ = 5.85e−5

The same, minus what the episode actually cost in milliseconds. I fitted those three coefficients on an M4 Max rather than guessing them.

The thing to notice is that the cost is inside the correct branch. If the answer is wrong the reward is 0 no matter how fast we got there, so the model can never buy speed by being wrong. That is what keeps the two runs comparable on accuracy — not luck, just where we put the parenthesis.

2Results

Both runs share the same code, the same data in the same order, the same seed and the same wall-clock budget. The only thing that changes is λ. So anything we see below is caused by the cost term and nothing else.

3What looking buys

Before comparing the two runs, it is worth checking the tool is doing anything at all. So we take the same policy and the same 96 V*Bench questions, and run them twice — once with the zoom tool available, once with it taken away. V*Bench is 191 high-resolution photos, around 2250×1500, where the thing being asked about covers roughly 0.06% of the frame. That is small enough that a downscaled view genuinely cannot answer it, which is exactly the setting we want.

4Across quantizations

Quantization is usually treated as a speed knob. It is not only that — it also changes how much the model says, and since decode tokens dominate the cost, that changes what an episode costs.
