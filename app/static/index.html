Cost-aware visual search

A 4B vision model decides where to look in a high-resolution image. The reward charges milliseconds measured on the machine it ships to, not a token count. Same accuracy, 2.2× faster on device.

How to read these numbers
Accuracy is measured on the training rig — 3×RTX 3090, bf16, all 191 V*Bench images. GPU time is cheap there, so everything runs.
Prefill, decode, latency and cost are measured on the M4 Max at Q4_K_M, on 36 images. Fewer, because each episode must run serially — two timing jobs on one Metal GPU corrupt each other — and because the Mac is the deployment target, which is the only place a latency number means anything. Two machines, two sample sizes, and each number is quoted from the machine where it is real.

Base vs. A vs. B

A and B are the same code, data, seed and training budget. The only difference is one term in the reward. Base is the untrained model in the same zoom environment.

What looking buys

The same policy on the same 96 reference images, once allowed to zoom and once forbidden. These 96 are all direct-attribute questions, a harder slice than the full 191 — so compare the two rows to each other, never to the 191-image number.
